================================================================================
                    BLE TRACKER — DATASET COLLECTOR INSTRUCTIONS
================================================================================

OVERVIEW
--------
This document outlines the procedure to collect RSSI (Received Signal Strength 
Indicator) datasets using the ESP32 BLE Beacon Scanner and the Python Dataset
Collector GUI Studio.

The data pipeline operates as follows:
  ESP32 WROOM-32E  ──(USB Serial / COM Port)──>  Python Collector GUI Studio  ──>  CSV Dataset

================================================================================
1. PREREQUISITES & ENVIRONMENT SETUP
================================================================================

1. Python Environment:
   Ensure Python 3.8+ is installed on your computer.

2. Install Required Dependencies:
   Open terminal or PowerShell in your project folder and run:

       py -m pip install pyserial

   Or inside your virtual environment:

       pip install pyserial

3. Project Directory Structure:
   
   ble tracker/
   ├── main/
   │   ├── CMakeLists.txt
   │   └── main.c               <-- ESP32 firmware source code
   ├── collector/
   │   ├── collector.py         <-- Collector GUI application
   │   ├── instructions.txt     <-- Collector instructions
   │   └── data/
   │       └── raw/             <-- Output CSV datasets saved here
   ├── instructions.txt         <-- Main instructions
   ├── CMakeLists.txt
   └── sdkconfig

================================================================================
2. ESP32 FIRMWARE DEPLOYMENT (IDF / PLATFORMIO / ESP-IDF)
================================================================================

1. Connect your ESP32 WROOM-32E board to your computer via a USB data cable.
2. Build and flash the firmware using ESP-IDF toolchain:

       idf.py build
       idf.py -p COM6 flash monitor

   (Replace COM6 with your actual ESP32 port).

3. ESP32 Data Stream Format:
   The ESP32 outputs CSV-formatted lines via UART Serial at 115200 baud rate:

       timestamp,anchor,mac,rssi,name
       12345,ANCHOR_01,D0:EF:76:58:F6:FE,-62,Unknown
       12365,ANCHOR_01,D0:EF:76:58:F6:FE,-63,Unknown

================================================================================
3. RUNNING THE DATASET COLLECTOR GUI
================================================================================

1. Launch the Collector Studio:

       py collector/collector.py

2. Select COM Port:
   - The GUI automatically detects connected ESP32 serial devices (CH340, CP210x, FTDI).
   - If your port isn't listed, plug in your ESP32 and click "🔄 Refresh Ports".

3. Set Baud Rate:
   - Ensure the baud rate is set to 115200 (default matching ESP32 firmware).

4. Enter Ground Truth Metadata:
   - Physical Distance (meters): Enter the exact measured distance between the 
     ESP32 scanner (anchor) and the BLE target beacon (e.g. 0.5, 1.0, 2.0, 5.0).
     Quick preset buttons (0.5m, 1.0m, 2.0m, 3.0m, 5.0m) are provided.
   - Obstacle: Select "No" for Line-of-Sight (LOS) experiments or "Yes" for Non-Line-of-Sight (NLOS).
   - Obstacle Type: If an obstacle is present, choose from presets (e.g., Human Body,
     Wooden Door, Concrete Wall, Metal Shield) or enter custom details.

5. Start Recording:
   - Click "▶ START RECORDING".
   - The GUI creates a timestamped file in `collector/data/raw/dataset_YYYY-MM-DD_HHMMSS.csv`.
   - Incoming RSSI samples and real-time sampling frequency (Hz) are displayed on screen.

6. Pause / Resume / Stop:
   - Click "⏸ PAUSE" if you need to reposition hardware temporarily without logging garbage data.
   - Click "⏹ STOP & SAVE" when you have acquired sufficient samples (e.g., 200–500 samples per distance point).

7. Open Output Directory:
   - Click "📁 Open Dataset Folder" in the GUI to access the raw CSV files directly.

================================================================================
4. DATASET SCHEMA & CSV FORMAT
================================================================================

The output CSV files contain the following columns:

Header:
timestamp,anchor,mac,rssi,name,distance_m,obstacle,obstacle_type

Example Records:
12345,ANCHOR_01,D0:EF:76:58:F6:FE,-62,Unknown,1.0,No,None
12365,ANCHOR_01,D0:EF:76:58:F6:FE,-63,Unknown,1.0,No,None
12385,ANCHOR_01,D0:EF:76:58:F6:FE,-61,Unknown,1.0,No,None
12405,ANCHOR_01,D0:EF:76:58:F6:FE,-64,Human Body,1.0,Yes,Human Body

Fields Description:
- timestamp     : ESP32 system timestamp (ms since boot)
- anchor        : Identifier of the scanning ESP32 node (e.g. ANCHOR_01)
- mac           : Target BLE transmitter MAC address
- rssi          : Measured Signal Strength in dBm (e.g. -62)
- name          : BLE device advertised name (if available)
- distance_m    : Ground truth distance measured in meters
- obstacle      : Binary flag ("No" or "Yes")
- obstacle_type : Material or type of obstacle ("None", "Human Body", etc.)

================================================================================
5. TROUBLESHOOTING & COMMON ISSUES
================================================================================

Issue: "No COM ports found"
Solution: 
  - Ensure the ESP32 USB cable supports DATA transfer (some cheap cables are power-only).
  - Verify Silicon Labs CP210x or CH340 USB-to-UART drivers are installed on Windows.

Issue: "PermissionError: Could not open port COMx"
Solution:
  - Close any open serial monitors (e.g., Serial Monitor in VS Code, Arduino IDE, PuTTY, or `idf.py monitor`).
  - Only one application can access a COM port at a time.

Issue: Garbage characters in Live Stream Console
Solution:
  - Verify the Baud Rate in the GUI matches the baud rate configured in your ESP32 `main.c` (default: 115200).
